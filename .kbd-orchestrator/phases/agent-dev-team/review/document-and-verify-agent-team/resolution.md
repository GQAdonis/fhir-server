# Review resolution: document-and-verify-agent-team (7 rounds)

**Method note.** The phase work was committed (and pushed for the 3-OS CI run) before this change's review. `build-review-packet.sh` diffs only against `HEAD`, and its file-tree pruning pattern `*/.git*` also hides `.github/`. So rounds 1–3 could not see the committed workflow and docs. From round 4 on, the orchestrator replaced the packet's `diff` with this change's files from `git diff main...HEAD`, plus uncommitted work and key evidence. Two follow-ups for the adversarial-review skill: add a base-ref option, and don't prune `.github`.

**Real defects fixed:**
- **Windows CRLF** (found by the first remote CI run): the lint parser read an empty prerequisites block, and the gofmt test fixture was CRLF. Fixed in code, with `.gitattributes eol=lf` for `*.go`, the agent files and the team doc.
- **Lint hardening:**
  - any tool both granted and disallowed is now reported (previously only the Edit+Write pair);
  - list-valued `model`/`name`/`description` are rejected;
  - path-like skill names are rejected and never resolved (a post-PASS warning, applied).
- **Spec wording:** CI compiles through `check:dist` (a temp-dir build with byte equality) instead of an in-place build, which would hide drift. Model-policy scope: the `local` lane is the Claude agent team, and the self-hosted `t4`/`l4` lanes may keep open-weight small/medium models.
- **Evidence:** per-OS exec-form lines recaptured (linux, darwin, win32); full `make test` output recorded; curator self-naming fixed and re-verified.

**Accepted warning (follow-up):** `.kbd-orchestrator/project.json` contains absolute local paths (`focus_project_path`, workspace folder). These are generated by `kbd-init` by design, and changing the KBD project format is out of scope.

**Persona gates:** `fhir-code-reviewer` PASS on the branch (`evidence/code-review-branch.txt`); `fhir-conformance-validator` goal check: all of G1–G5, C1 and C2 MET (`evidence/goal-check.txt`, gaps closed in `goal-check-gap-closure.txt`).
